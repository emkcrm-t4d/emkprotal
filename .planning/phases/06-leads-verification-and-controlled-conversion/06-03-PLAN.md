    Implement official communication infrastructure per LEAD-04, LEAD-07, and VERIFICATION-DICTIONARY.md Section 7:
    1. Create Mailable `app/Domain/Leads/Mail/MissingItemsNotificationMail.php`:
       - Queued mailable (implements `ShouldQueue`)
       - Receives `$lead`, `array $missingItems`, and `?string $customInstructions`
       - Blade view `resources/views/emails/leads/missing-items.blade.php` rendering formal EMK Center header, applicant greeting, bulleted checklist of missing/unreadable files, instructions, and front desk contact details
    2. Create Mailable `app/Domain/Leads/Mail/LeadRejectionMail.php`:
       - Queued mailable (implements `ShouldQueue`)
       - Receives `$lead`, `string $rejectionReasonCode`, and `string $applicantFacingMessage`
       - Blade view `resources/views/emails/leads/rejection.blade.php` rendering respectful formal notice with standardized explanation and reapplication guidance
    3. Create `app/Domain/Leads/Services/LeadCommunicationService.php`:
       - Method `sendMissingItemsNotification(Lead $lead, User $sender, array $missingItems, ?string $notes = null): void`:
         - Asserts sender has `leads.communicate` permission
         - Dispatches `MissingItemsNotificationMail` to `$lead->email`
         - Updates `$lead->status = 'missing_items'` and updates relevant stream status (e.g. document or photo to `missing_items` / `reupload_requested`)
         - Logs audit record with event `lead_missing_items_sent` capturing sender ID and item list
       - Method `rejectLead(Lead $lead, User $manager, string $rejectionReasonCode, ?string $internalNotes = null): void`:
         - Asserts manager has managerial `leads.reject` permission per MODULE-REGISTRY.md
         - Validates `$rejectionReasonCode` against standardized taxonomy in VERIFICATION-DICTIONARY.md Section 7: `INVALID_TXID`, `AMOUNT_MISMATCH`, `DUPLICATE_TXID`, `TRANSACTION_NOT_FOUND`, `DOCUMENT_UNREADABLE`, `EXPIRED_ID`, `NAME_MISMATCH`, `MISSING_GUARDIAN_CONSENT`, `NON_COMPLIANT_BACKGROUND`, `SELFIE_DETECTED`, `GLASSES_OBSCURING_FACE`, `EARS_COVERED`, `LOW_RESOLUTION`
         - Dispatches `LeadRejectionMail` with mapped applicant-facing explanation
         - Transitions `$lead->status = 'rejected'`
         - Logs audit record with event `lead_rejected` capturing code and internal notes
       - Method `blockApplicantEmail(Lead $lead, User $manager, string $justification): void`:
         - Asserts manager has managerial `leads.reject` permission (Workspace Manager only)
         - Transitions `$lead->status = 'blocked'`
         - Logs audit record with event `lead_blocked` capturing justification and email
    4. Create unit test `tests/Unit/LeadCommunicationServiceTest.php`:
       - Tests `sendMissingItemsNotification` dispatches mail, transitions status, and records audit
       - Tests `rejectLead` validates reason code against taxonomy, dispatches rejection mail, and transitions status to `rejected`
       - Tests `blockApplicantEmail` updates status to `blocked`
       - Tests authorization gates preventing unauthorized staff from rejecting or blocking leads
  </action>

    - Unit tests pass with 100% assertions satisfied.
