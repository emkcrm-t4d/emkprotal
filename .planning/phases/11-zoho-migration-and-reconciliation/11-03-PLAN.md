    Implement `ReconciliationReportDTO` and `ZohoReconciliationService` to compare source Zoho datasets against imported Hub records per MIGR-04:
    1. Define `App\Domain\Migration\DTOs\ReconciliationReportDTO`:
       - Properties:
         - `string $batchUuid`, `string $workspaceId`, `string $generatedAt`.
         - Counts: `int $sourceRecordCount`, `int $importedRecordCount`, `int $discrepancyCount`.
         - Status distribution: `array $sourceStatusCounts`, `array $importedStatusCounts`.
         - Unique email metrics: `int $sourceUniqueEmails`, `int $importedUniqueEmails`, `array $duplicateEmails`.
         - Date fidelity metrics: `int $dateMismatchCount`.
         - Attachment completeness: `int $expectedAttachments`, `int $actualAttachments`, `int $missingAttachments`.
         - Discrepancy collection: `array<int, array{zoho_id: string, entity: string, field: string, expected: mixed, actual: mixed, severity: string, message: string}>`.
         - Helper: `isReconciled(): bool` returning true only when discrepancyCount is 0.
         - Helper: `matchPercentage(): float` returning matched percentage formatted to 2 decimals.
    2. Implement `App\Domain\Migration\Services\ZohoReconciliationService`:
       - Method `reconcileBatch(ZohoImportBatch $batch): ReconciliationReportDTO`:
         - Scoped to `$batch->workspace_id`.
         - Step 1: Compare total staging records in batch with target entity records where `zoho_id` matches.
         - Step 2: Compare status distributions (e.g. Active in Zoho vs active in `members`, Rejected in Zoho vs rejected in `leads`). Flag status mismatches.
         - Step 3: Check email uniqueness: detect if any source email maps to multiple Zoho IDs or fails Hub email format.
         - Step 4: Verify key date integrity: compare `start_date`, `expiry_date`, and `date_of_birth` between staging payload and persisted model.
         - Step 5: Check attachment matching: for each member with expected attachments, verify corresponding `lead_attachments` record exists and file exists on private disk.
         - Aggregate discrepancies into DTO with severity levels: 'critical' (missing record, wrong email, missing required document), 'warning' (status mismatch, non-fatal date deviation), 'info' (address format variance).
       - Method `reconcileWorkspace(string $workspaceId): ReconciliationReportDTO` for holistic workspace-level audit.
    3. Author `tests/Feature/ZohoReconciliationReportTest.php`:
       - Test reconciliation on 100% matching dataset returns `isReconciled() === true` and match percentage 100.0%.
       - Test detection of count mismatch when records are omitted.
       - Test detection of email duplication or formatting divergence.
       - Test detection of date discrepancies.
       - Test detection of missing attachments on private disk.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator Console → Reconciliation Query | CLI arguments dictate query parameters across staging and core tables |
| Livewire Request → Reconciliation Dashboard | Web users query migration discrepancies across tenant boundaries |
| Report Export → Browser Download | Potentially sensitive member PII is rendered in CSV/HTML downloads |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-07 | Information Disclosure | ReconciliationDashboard | high | mitigate | Enforce workspace.access middleware and can:migration.reconcile_data permission; scope all discrepancy queries to authorized workspace |
| T-11-08 | Denial of Service | ZohoReconciliationService | medium | mitigate | Optimize queries with indexed joins on zoho_id and workspace_id; paginate discrepancy tables to prevent memory exhaustion |
| T-11-09 | Tampering | ReconciliationReportGenerator | medium | mitigate | Sanitize all field values in CSV/HTML exports to prevent CSV formula injection (=, +, -, @) and XSS |
| T-11-SC | Tampering | npm/pip/cargo installs | high | mitigate | Package legitimacy gate + blocking human checkpoint for assumed/sus packages |
</threat_model>
