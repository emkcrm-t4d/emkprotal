    Implement transactional dry-run simulation and inactive portal account provisioning per MIGR-05 and DEC-06:
    1. Implement `App\Domain\Migration\Services\ZohoDryRunEngine`:
       - Method `executeDryRun(string $filePath, string $workspaceId, string $sourceType): array`:
         - Opens explicit transaction: `DB::beginTransaction()`.
         - Executes staging and ingestion via `ZohoDataIngestionService`.
         - Executes mock attachment association without permanent disk writes.
         - Runs reconciliation check via `ZohoReconciliationService`.
         - Collects simulation metrics: staged count, transformed count, validation errors, reconciliation match rate.
         - Invariably rolls back: `DB::rollBack()` in `finally` block to guarantee 0 database writes.
         - Returns detailed dry-run report payload.
    2. Implement `App\Domain\Migration\Services\PortalAccountProvisioningService`:
       - Method `provisionInactiveAccounts(string $workspaceId, ?string $batchUuid = null): array`:
         - Queries members in workspace imported from Zoho (`whereNotNull('zoho_id')`) that lack an associated portal user account.
         - For each member:
           - Insert into `users` table:
             - `name`: member's full name.
             - `email`: member's verified email.
             - `password`: `null` (no default password per DEC-06).
             - `guard`: `'member'`.
             - `is_active`: `false` (account inactive until claimed).
             - `must_reset_password`: `true`.
             - `workspace_id`: `$workspaceId`.
             - `zoho_id`: member's `zoho_id`.
           - Update `members.user_id` with new user record ID.
           - Log immutable audit event in `audit_logs` (`event_type = 'portal_account_staged_inactive'`).
         - Return count of staged accounts.
       - Method `assertAccountCannotLogin(User $user): bool`: confirms authentication fails closed while `is_active = false`.
    3. Implement Artisan commands:
       - `ZohoDryRunCommand` (`zoho:dry-run {file} {--workspace=ws-emk-dhaka} {--type=contacts_members}`): executes dry-run engine, displays console summary table, and verifies rollback.
       - `ZohoProvisionPortalAccountsCommand` (`zoho:provision-portal-accounts {--workspace=ws-emk-dhaka} {--batch=}`): provisions inactive portal accounts with progress bar.
    4. Author `tests/Feature/ZohoDryRunAndCutoverTest.php`:
       - Assert dry-run executes full ingestion simulation and leaves database completely unchanged (record counts identical before and after).
       - Assert dry-run detects validation errors and reports them in console.
       - Assert portal accounts are provisioned with `guard = 'member'`, `is_active = false`, and `password = null`.
       - Assert attempting to authenticate with inactive staged portal account is rejected.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator Console → Dry-Run Execution | Operator runs simulation that must never commit changes to production database |
| Migration Engine → User Accounts Table | Batch user creation must never grant unauthenticated access or active sessions |
| Delta Exporter → Zoho CSV Export | Application records exported during rollback contain sensitive PII |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-10 | Tampering | ZohoDryRunEngine | critical | mitigate | Wrap all dry-run execution in DB::beginTransaction() with mandatory DB::rollBack() in finally block; assert database state is unchanged |
| T-11-11 | Elevation of Privilege | PortalAccountProvisioningService | critical | mitigate | Provision portal accounts with is_active = false, must_reset_password = true, and password = null; enforce authentication guard rejection |
| T-11-12 | Information Disclosure | HubDeltaExportService | high | mitigate | Protect exported CSV file permissions (0600), sanitize cells against CSV injection (=, +, -, @), and restrict command execution to Superadmin |
| T-11-SC | Tampering | npm/pip/cargo installs | high | mitigate | Package legitimacy gate + blocking human checkpoint for assumed/sus packages |
</threat_model>
