    1. Enhance `app/Domain/Members/Services/MemberChangeRequestService.php`:
       - Add method `approveEmailChangeRequest(MemberChangeRequest $request, User $reviewerUser): void`:
         - Verify reviewer authority: Must possess `workspace_manager`, `superadmin`, or `global_admin` role. Delegated staff cannot approve email changes per DEC-07 and T-01-07.
         - Assert `$request->request_type === MemberChangeRequest::TYPE_EMAIL_CHANGE`.
         - Assert `$request->status === MemberChangeRequest::STATUS_PENDING`.
         - Execute inside `DB::transaction()`:
           - Lock the request row: `$lockedRequest = MemberChangeRequest::where('id', $request->id)->lockForUpdate()->firstOrFail();`.
           - Lock the member row: `$member = Member::where('id', $request->member_id)->lockForUpdate()->firstOrFail();`.
           - Lock the linked user row: `$user = User::where('id', $member->user_id)->lockForUpdate()->firstOrFail();`.
           - TOCTOU Race Condition Defense (T-09-12): Re-assert that `$lockedRequest->new_payload['email']` has not been registered in `users` or `members` between submission and approval.
             If conflict exists, throw `\DomainException('The requested new email has been claimed by another user prior to approval.')`.
           - Atomic Dual-Entity Update:
             - Update `$member->email = $lockedRequest->new_payload['email']; $member->save();`
             - Update `$user->email = $lockedRequest->new_payload['email']; $user->save();`
           - Transition request status:
             `$lockedRequest->update(['status' => MemberChangeRequest::STATUS_APPROVED, 'reviewed_by_user_id' => $reviewerUser->id, 'reviewed_at' => now()]);`
           - Emit immutable `AuditLog` entry (`event_type = 'member_email_changed'`):
             `actor_id = $reviewerUser->id`, `actor_guard = 'web'`, `auditable_type = Member::class`, `auditable_id = $member->id`, `workspace_id = $member->workspace_id`, `old_values = ['email' => $request->old_payload['email']]`, `new_values = ['email' => $request->new_payload['email']]`, `reason = "Manager approved email change request #{$request->id}: {$request->justification}"`.
           - Trigger workflow rule `WorkflowRule::TRIGGER_REQUEST_OUTCOME` ('member.change_request_outcome').
    2. Update `app/Livewire/Members/MemberChangeRequestDirectory.php`:
       - Highlight email change requests with an amber security badge: "Email Address Change (Requires Manager Approval)".
       - Restrict the "Approve" button on email change items to users with `workspace_manager` role or superadmins (disabled with tooltip for delegated staff).
       - Clicking Approve calls `MemberChangeRequestService::approveEmailChangeRequest`, flashes success toast: "Member email successfully updated across portal credentials and member profile.", and refreshes table.

|----------|-------------|
| Member Portal → Login Credentials | Changing email changes the primary authentication identifier |
| Staff Role Boundary | Delegated staff must not have authority to approve email changes |
| Concurrency / TOCTOU Boundary | Email claimed between submission and approval must not cause database constraint crash |

| T-09-11 | Data Inconsistency / Denial of Service | MemberChangeRequestService | high | mitigate | Wrap the dual-entity update in an atomic DB transaction with pessimistic locking, guaranteeing members.email and users.email never diverge. |
