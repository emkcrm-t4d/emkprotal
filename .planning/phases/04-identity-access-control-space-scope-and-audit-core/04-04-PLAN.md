<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Domain Models -> Audit Log Table | Domain entities containing sensitive user credentials (passwords, tokens, bKash PINs) could leak into audit logs |
| Database Client -> audit_logs Table | Rogue user or compromised database credential could attempt to tamper with or erase forensic audit records |
| Authentication System -> Audit Logger | Login failure events could accidentally log submitted plaintext passwords |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-10 | Information Disclosure | AuditableObserver Data Redaction | critical | mitigate | Implement strict SENSITIVE_KEYS regex allowlist in AuditableObserver replacing passwords, tokens, API keys, and bKash PINs with [REDACTED] per DEC-11 and ASVS V8.2. |
| T-04-11 | Repudiation / Tampering | Database Audit Trigger Boundary | critical | mitigate | Enforce MySQL triggers trg_audit_logs_prevent_update and trg_audit_logs_prevent_delete rejecting UPDATE and DELETE with SQLSTATE 45000 per DEC-11. |
| T-04-12 | Information Disclosure | Authentication Failure Logger | high | mitigate | In AuditAuthenticationEvents for Failed event, record attempted username/email but explicitly omit credentials['password'] from audit payload. |
| T-04-SC | Tampering | npm/composer installs | high | mitigate | Package-legitimacy gate: native Laravel Eloquent observers and database triggers; zero third-party logging binaries. |
</threat_model>
