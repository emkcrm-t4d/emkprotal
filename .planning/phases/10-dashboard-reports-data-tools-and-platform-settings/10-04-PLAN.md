       - Define encryption algorithm: `'AES-256-CBC'`.
       - Define retention days: `30`.

       - Define tables included: all core CRM tables (`workspaces`, `spaces`, `users`, `membership_terms`, `member_id_sequences`, `leads`, `lead_attachments`, `lead_verifications`, `members`, `invoices`, `id_cards`, `member_change_requests`, `audit_logs`, `platform_settings`, `email_messages`, `email_threads`, `email_templates`, `workflow_rules`, `forms`, `form_submissions`).
    2. Update `app/Domain/Audit/Models/AuditLog.php`:
       - Add constants:
         - `public const EVENT_BACKUP_CREATED = 'backup_created';`
         - `public const EVENT_BACKUP_RESTORE_VERIFIED = 'backup_restore_verified';`
         - `public const EVENT_BACKUP_DELETED = 'backup_deleted';`
    3. Create Service `app/Domain/Platform/Services/BackupService.php`:
       - Methods:
         - `public function createBackup(bool $includeDocuments = true, bool $encrypt = true): array`:
           - Acquire atomic cache lock: `Cache::lock('platform_backup_lock', 600)->get()`. If lock cannot be acquired, throw runtime exception 'A backup operation is currently in progress.'.
           - Dump Database:
             - When running against MySQL, generate SQL dump via mysqldump or PDO table cursor export.
             - When running in SQLite/testing environment, export table DDL and row data to `.sql` file.
           - Package Private Documents:
             - If `$includeDocuments` is true, bundle files from `storage/app/private/` into the archive structure.
           - Create ZIP Archive:
             - Bundle SQL dump + documents manifest into archive: `backup-{$timestamp}.zip`.
           - Encrypt Archive (T-10-10):
             - If `$encrypt` is true, encrypt raw ZIP using AES-256-CBC via `openssl_encrypt()` or Laravel `Crypt::encrypt()` to produce `backup-{$timestamp}.zip.enc`.
             - Remove unencrypted intermediate file.
           - Generate Checksum Manifest (T-10-12):
             - Compute SHA-256 hash of final archive: `hash_file('sha256', $archivePath)`.
             - Write alongside archive: `backup-{$timestamp}.zip.enc.sha256`.
           - Prune old archives per retention policy (default 30 days).
           - Release atomic cache lock.
           - Record `AuditLog::EVENT_BACKUP_CREATED` with archive name, size, hash, and status.
           - Return array: `['status' => 'success', 'filename' => $filename, 'size' => $size, 'sha256' => $hash, 'encrypted' => $encrypt]`.
         - `public function verifyArchive(string $archiveFilename): array`:
           - Locate archive and `.sha256` manifest in `storage/app/backups/`.
           - Check file exists and has size > 0.
           - Verify SHA-256 checksum matches manifest exactly. If mismatch, return `['valid' => false, 'error' => 'Checksum verification failed: archive may be corrupted or tampered.']`.
           - Attempt decryption test with encryption key. If decryption fails, return `['valid' => false, 'error' => 'Decryption failed: invalid key.']`.
           - Inspect ZIP table structure (confirm database dump and valid header exists).
           - Record `AuditLog::EVENT_BACKUP_RESTORE_VERIFIED`.
           - Return `['valid' => true, 'archive' => $archiveFilename, 'checksum_verified' => true, 'decryption_verified' => true]`.
         - `public function listBackups(): array`:
           - Scans `storage/app/backups/` and returns sorted list of backup metadata (name, date, size_bytes, encrypted, sha256).
    4. Create Artisan Command `app/Console/Commands/CreatePlatformBackupCommand.php`:
       - Signature: `crm:backup:create {--no-docs : Exclude private storage documents} {--no-encrypt : Skip AES-256 encryption}`
       - Description: 'Create a full encrypted backup of the database and private member documents'
       - Invokes `BackupService->createBackup()` and outputs status with SHA-256 hash.
    5. Create Artisan Command `app/Console/Commands/VerifyPlatformBackupCommand.php`:
       - Signature: `crm:backup:verify {archive : The backup archive filename}`
       - Description: 'Verify the integrity, checksum, and decryptability of a backup archive'
       - Invokes `BackupService->verifyArchive()` and prints PASS / FAIL status.
    6. Author `tests/Feature/BackupEngineTest.php`:
       - Assert `crm:backup:create` generates an encrypted archive and `.sha256` manifest.
       - Assert archive is encrypted and raw ZIP cannot be uncompressed without decryption.
       - Assert `crm:backup:verify` confirms valid archive integrity.
       - Assert corrupting one byte in the archive causes verification to fail with checksum error.
       - Assert attempting concurrent backup while lock is active is rejected.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server Storage → Backup Disk | Sensitive member PII, identity documents, and credentials archived to disk |
| Web Download Endpoint → Client Admin | Encrypted archive download crosses HTTP network boundary |
| Backup Restore → Production Database | Untrusted or corrupted archive could destroy database if restored unchecked |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-10 | Information Disclosure | BackupService Archive Storage | high | mitigate | Encrypt all database dumps and private documents inside the backup archive using AES-256-CBC, store in a restricted storage disk outside the web root, and restrict download endpoints to superadmin/workspace_manager. |
| T-10-11 | Denial of Service | BackupService Concurrency | medium | mitigate | Acquire an atomic cache lock ('platform_backup_lock') with a 10-minute timeout before backup execution; fail-fast if a backup is already in progress. |
| T-10-12 | Tampering | VerifyPlatformBackupCommand | high | mitigate | Calculate SHA-256 manifest upon archive generation, and mandate cryptographic hash verification, decryption validation, and structure check prior to any restore action. |
| T-10-SC | Tampering | npm/pip/cargo installs | high | mitigate | package-legitimacy gate + blocking human checkpoint for assumed/sus packages. |
</threat_model>
