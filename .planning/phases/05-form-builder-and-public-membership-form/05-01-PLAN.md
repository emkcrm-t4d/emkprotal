    Create `app/Domain/Forms/Services/FormSchemaEngine.php` implementing dynamic schema manipulation without dynamic code evaluation (adhering strictly to DEC-02 and the Zero-Eval architectural invariant).

    The service must support the complete catalog of field types specified in FORM-01 and the source specification:
    - `text`: single-line string with casing options (none, uppercase, lowercase, capitalize), min/max length, regex pattern.
    - `email`: email input with RFC/DNS validation flag and uniqueness flag.
    - `select`: single-select dropdown with static options or dynamic dataset keys (e.g., `bangladesh_divisions`, `american_spaces`).
    - `cascading_select`: child dropdown depending on a parent field value (e.g., `address_division` -> `address_district`).
    - `radio`: single-choice radio options or boolean radio (`yes_no`).
    - `checkbox`: standalone agreement checkbox (e.g., `terms_agreed`) or multi-select checkbox group.
    - `date`: date picker with format specification, before/after constraints, and age computation trigger.
    - `file`: single file upload with permitted mime types, max size in KB, and dimension constraints (for studio passport photos).
    - `multi_file`: multiple file upload with min/max file count, permitted mime types, and max size per file.
    - `number`: numeric input with min, max, step, and integer constraints.
    - `textarea`: multi-line text input with character limits.
    - `instructions`: informational text block / notice box with styling attributes (info, warning, danger).
    - `section_break`: visual divider and section grouping for multi-part forms.

    The engine must provide methods:
    - `validateSchema(array $schema): bool`: validates structure of field definitions, ensuring unique field keys, valid field types, required properties, and absence of malformed operators.
    - `normalizeField(array $field): array`: applies default attributes (required, visible, conditional rules, validation rules, help text).
    - `evaluateVisibility(array $field, array $formData): bool`: evaluates conditional visibility rules (e.g., show Field 7 if age < 18, show Field 22 if has_us_experience is true) without using eval().
    - `getFieldCatalog(): array`: returns metadata describing all supported field types, valid configuration keys, and default options.

    1. `compileRules(array $schema, array $inputData = []): array`:
       - Iterates normalized fields and builds Laravel validator rule arrays.
       - Translates field constraints to rules: `required`, `nullable`, `string`, `min:X`, `max:Y`, `regex:PATTERN`, `email:rfc`, `in:OPTIONS`, `mimes:EXTS`, `max:KB`.
       - For cascading select fields (e.g. `address_district`), generates dynamic `in:...` rule matching allowed districts for the currently selected `address_division` per FIELD-DICTIONARY.md Section 4.

       - For bKash Transaction ID (Field 30), generates rule requiring exactly 10 uppercase alphanumeric characters (`size:10, regex:/^[A-Z0-9]{10}$/`).

       - Generates human-friendly error messages customized per field (e.g., "Parental/Guardian consent form is mandatory for applicants under 18 years of age.", "Please enter a valid 10-character uppercase bKash Transaction ID (e.g., BLK7X9Q12M).").
    3. `sanitizePayload(array $schema, array $inputData): array`:
       - Trims whitespace from string inputs.
       - Sanitizes text inputs by stripping disallowed control characters while preserving standard punctuation for transliterated names (apostrophes, hyphens, periods, spaces) per FIELD-DICTIONARY.md Section 2.
