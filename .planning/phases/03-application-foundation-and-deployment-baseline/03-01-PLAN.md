<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client / External -> Web Server (/up, /healthz) | Unauthenticated external requests probe health endpoints; internal environment details must not be leaked |
| Web Application -> MySQL 8.4 & Redis services | Internal data queries and queue payloads pass through local network or unix socket boundaries |
| Deployment Environment -> CI Workflow & GitHub Actions | Untrusted pull request payloads or workflow definitions could execute malicious code |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information Disclosure | Health Probe Endpoints (/up, /healthz) | medium | mitigate | Restrict /healthz response payload to minimal status indicators (ok, timestamp) without exposing database credentials, internal server paths, or stack traces per FOUN-05. |
| T-03-02 | Denial of Service | Redis Queue / Horizon Workers | medium | mitigate | Configure maxProcesses and retry limits in config/horizon.php, and route failed jobs to failed_jobs table to prevent worker loop exhaustion. |
| T-03-03 | Tampering | GitHub Actions CI Pipeline | high | mitigate | Pin GitHub Actions to verified actions (actions/checkout, shivammathur/setup-php), enforce cancel-in-progress concurrency, and require strict composer audit checks. |
| T-03-SC | Tampering | npm/composer installs | high | mitigate | Package-legitimacy audit verified; use verified composer and npm packages only. |
</threat_model>
