<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public Applicant / Staff -> File Upload Endpoint | Uploaded file payloads could contain malware, path traversal sequences, or excessive file sizes |
| Client Web Server -> Private Storage (storage/app/private) | Files stored on disk must not be accessible via direct HTTP requests or web server symlinks |
| Authenticated Staff -> DocumentDownloadController Endpoint | Authenticated staff from one workspace might attempt to download documents belonging to another workspace |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-10 | Information Disclosure | Storage Filesystem (/storage/app/private) | critical | mitigate | Configure private storage disk outside public web root with zero web symlinks; rename files with cryptographic UUID v4 strings to prevent direct URL prediction per DEC-09. |
| T-03-11 | Information Disclosure | DocumentDownloadController | high | mitigate | Enforce multi-workspace isolation (abort 403 if user workspace != lead workspace) and require leads.view_youth_records for minor documents per DEC-09. |
| T-03-12 | Tampering | DocumentStorageService | high | mitigate | Compute SHA-256 integrity hash on upload, encrypt sensitive files at rest with AES-256, and validate hashes prior to streaming per ARCH-06 and DEC-09. |
| T-03-SC | Tampering | npm/composer installs | high | mitigate | Package-legitimacy audit verified; use verified composer and npm packages only. |
</threat_model>
